# Исследование: module_system — цепочка спецификаций

Связь: [`../AgentSpecificationResearch.md`](../AgentSpecificationResearch.md) — гипотезы и метрики; **этот файл** — журнал пилота и корреляция артефактов.

**Стандарт форматирования (не домен):** `yaml_spec_convention.yaml`, `yaml_spec_convention-mini.yaml` (корень репозитория).

---

## Цепочка происхождения (важно для метрик)

Исходный эталон домена — **не** `module_system.md`. Порядок такой:

```text
[L0] module_system.yaml          ← эталон домена (legacy yaml в репозитории)
        │
        │  (ручная / агентная конвертация в prose)
        ▼
[L1] module_system.md            ← вход для эксперимента md→yaml
        │
        │  фаза 1: md → yaml (mini), промпт, 3 модели
        ▼
[L2] <прогон>/module_system-TEST.yaml
        │
        │  фаза 2: yaml → md, только TEST.yaml
        ▼
[L3] <прогон>/module_system-REVERSE.md
```

| Слой | Файл | Роль в расчёте |
|------|------|----------------|
| **L0** | `module_system_conversion_results/module_system.yaml` | **Эталон домена** — с чем сравниваем «вернулись ли к исходной спеке» |
| **L1** | `module_system_conversion_results/module_system.md` | Производный от L0; **вход фазы 1** (уже не полный эталон) |
| **L2** | `module_system-TEST.yaml` | Выход фазы 1; **вход фазы 2** |
| **L3** | `module_system-REVERSE.md` | Выход фазы 2 |

**Следствие:** потеря «REVERSE vs md» **не равна** только ошибке фазы 2. Часть «дыр» в REVERSE — потому что их **не было в L2**, а их не было в L2 — потому что **не было в L1**, хотя могло быть в **L0** (или наоборот: в L1 есть prose, которого нет в L0).

`module_system.yaml` в прогонах **запрещали читать** — модели не видели L0; сравнение с L0 делает исследователь постфактум.

## Что есть только в L0 / L1 / обоих (для корреляции)

| Факт | L0 yaml | L1 md | Комментарий |
|------|:-------:|:-----:|-------------|
| `conforms_to` / mini | частично (full convention) | нет (frontmatter skill) | L1 — другая шапка |
| Frontmatter `description` | нет | **да** | в L1 из prose; в L2 обычно нет |
| Config layers как таблица Source/Helper | нет (`env_settings_model`) | **да** | разная форма, смысл близкий |
| `clearModulesCache()` в тексте caching | нет в `invalidate_after` | **да** | L0 test3 тоже без admin/clear в списке |
| Helpers с пояснением источника (`→ module.json`) | кратко в key_functions | **да** | |
| Правило «перед правками — слой + path» (стр. 15) | нет отдельным блоком | **да** | |
| `module_json` / `admin_integration` имена | **да** | переформулировано | L2 → `manifest`, `integration` |

При разборе потерь помечать: **Δ(L0→L1)** | **Δ(L1→L2)** | **Δ(L2→L3)** и **критичность** (шкала ниже).

## Шкала критичности (criticality)

Оценка влияния на агента/код, если использовать артефакт **как единственную спеку** (без L0 и без кода репозитория).

| Уровень | Код | Смысл | Пример |
|---------|-----|--------|--------|
| **C0** | critical | Неверное решение в runtime; политика безопасности/данных | helper записан в `runtime_overrides` (test2 L2) |
| **C1** | high | Высокий риск нарушения `do_not` или выбора неверного слоя | нет явного read_priority / write_behavior в L2 |
| **C2** | medium | Неполнота; опытный агент компенсирует, junior — ошибётся | нет `clearModulesCache` в caching |
| **C3** | low | Имена блоков, язык, порядок секций; grep по коду спасает | `manifest` vs `module_json` |
| **C4** | negligible | Намеренная нормализация mini; на код не влияет | обёртка `body:`, `conforms_to` |
| **HX** | healing | L3 лучше L2 по смыслу **без основания в L2** — ложный успех бенчмарка | test2: слои в REVERSE при битом yaml |

**Агрегат прогона:** максимальный уровень по всем находкам в L2 (для кода) или L3 (если читают md).

| Прогон | Max в L2 | Max в L3 | Пригодность для кода |
|--------|----------|----------|----------------------|
| test | C2 | **C1** | да с оговорками (path warning в L3) |
| test2 | **C0** | **HX** + C2 | **нет** как эталон |
| test3 | C2 | C2 | **да** (рекомендован) |

## Критичность по переходам (сводка)

| Переход | Доминирующий риск | test | test2 | test3 |
|---------|---------------------|------|-------|-------|
| L0→L1 | L1 богаче prose, беднее vs mini | C2 | C2 | C2 |
| L1→L2 | семантика слоёв | C2 | **C0** | C2 |
| L2→L3 | fidelity к L2 | **C1** | **HX** | C2 |
| L0→L3 (цепочка) | не вернуть L0 | C3 | C0/HX | C2 |

**Вывод по criticality:** единственный **C0** в пилоте — test2 L2. Для production-like спеки минимальный порог — **нет C0/C1 в L2**; test3 укладывается (максимум C2). **C2** допустим, если в фазе «код» проверять cache/layer violations отдельно.

## Фаза 1: L1 (md) → L2 (yaml)

### Протокол

| Параметр | Значение |
|----------|----------|
| Вход | `module_system.md` + `yaml_spec_convention-mini.yaml` |
| Эталон сравнения (постфактум) | **L0** `module_system.yaml` и/или **L1** |
| Запрет в прогоне | не читать L0 и другие файлы |
| Выход | `<прогон>/module_system-TEST.yaml` |

### Сводная таблица

| Прогон | Модель | Строк L2 | L2 vs **L1** | L2 vs **L0** | Max crit L2 |
|--------|--------|----------|--------------|--------------|-------------|
| `test/` | Composer | ~218 | ~98% | ~60% формы | **C2** |
| `test2/` | Gemini 3 Flash | ~95 | ~85% | ниже | **C0** |
| `test3/` | GPT-5.5 | ~213 | ~96% | ~65% формы | **C2** |

**L2 vs L0** — не «потеря конвертации», а **расхождение с legacy-эталоном** + mini-нормализация (`config_layers`, `body`, `manifest`).

**Лучший L2:** `test3/module_system-TEST.yaml`.

## Фаза 2: L2 (yaml) → L3 (md)

### Протокол

| Параметр | Значение |
|----------|----------|
| Вход | только `module_system-TEST.yaml` того же прогона |
| Запрет | не читать L0, L1 и другие файлы |
| Выход | `module_system-REVERSE.md` |

### Корректные сравнения (не путать)

| Сравнение | Что измеряет |
|-----------|----------------|
| **L3 vs L2** | Чистая потеря/добавление при yaml→md (**фаза 2**) |
| **L3 vs L1** | Круг от входа пилота (md→yaml→md) |
| **L3 vs L0** | Возврат к доменному эталону (полная цепочка) |

**Неверно:** считать все «дыры L3 vs L1» ошибкой фазы 2 — сначала проверить, было ли поле в **L2**.

### Сводная таблица

| Прогон | Модель | Строк L3 | **L3 vs L2** | **L3 vs L1** | Max crit L3 |
|--------|--------|----------|--------------|--------------|-------------|
| `test/` | Composer | ~310 | высокое (C1: path warning) | ~92–94% | **C1** |
| `test2/` | Gemini | ~179 | неполная реконструкция | ~82–85% | **HX** |
| `test3/` | GPT-5.5 | ~300 | высокое | ~93–95% | **C2** |

### Примеры разнесения по слоям (test3)

| Факт | L0 | L1 | L2 | L3 | Crit | Вывод |
|------|----|----|----|----|------|-------|
| `clearModulesCache` в caching | нет | да | нет | нет | C2 | Δ(L1→L2)→Δ(L2→L3) |
| Frontmatter `description` | нет | да | нет | нет | C4 | не для runtime-кода |
| Helpers `→ module.json` | кратко | да | имена | имена | C2 | Δ(L1→L2) |
| `body.*` в do_not prose | нет | нет | да | да | C3 | утечка структуры yaml |
| Слои + helpers | иначе | таблица | ok | ok | C4 | форма; test3 смысл ok |
| path warning полнота | да | да | короче | короче | C1 | test3: риск недооценки path |

### Healing (test2)

L2 test2: неверные `runtime_overrides`. L3 test2: слои в md **описаны верно**. Это **не** попадание в L0 — возможное восстановление моделью при записи md. Считать отдельной метрикой, не как качество L2.

## Полная цепочка L0 → L1 → L2 → L3

| Переход | test3 (ориентир) | Смысл |
|---------|------------------|--------|
| L0 → L1 | prose, frontmatter, таблицы | md уже другой носитель, не копия yaml |
| L1 → L2 | ~96% фактов L1, ~65% формы L0 | mini + модель меняют имена блоков |
| L2 → L3 | ~93–95% vs L1 при полном L2 | обратная перегонка в основном держит L2 |
| L0 → L3 (напрямую) | не идемпотентно | нельзя ожидать восстановления legacy-yaml |

**Итог пилота:** эксперимент тестировал **L1→L2→L3**. Эталон домена **L0** подключается при интерпретации; «вернуть yaml как в L0» этим промптом **не ставилось**.

## Итоговые выводы

1. **Эталон домена** — `module_system.yaml` (L0). **Вход пилота** — `module_system.md` (L1), уже производный.
2. **Фаза 1** — насколько из L1 восстанавливается структурированный контракт; близость к L0 отдельная колонка.
3. **Фаза 2** — в первую очередь **L3 vs L2**; L3 vs L1 — круг от md-входа; L3 vs L0 — полная дельта от эталона.
4. Для кода и токенов — **L2 test3**, не L3. L0 — референс ревью, если нужен legacy-формат.
5. Преимущество structured yaml — при качественном L2; md (L1) и REVERSE (L3) — производные, с накоплением Δ по цепочке.
6. **Criticality:** порог для спеки под код — **max C2 в L2**, ноль **C0**; учитывать **HX** при оценке L3 (test2 не показателен).
